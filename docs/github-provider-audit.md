# فحص المزوّدين عبر GitHub Actions

## الحالة الفعلية

هذه **مرحلة اكتشاف وإعداد**، لا تقرير نجاح للمفاتيح المنشورة في المحادثة. لم تُستخدم تلك المفاتيح، ولا توجد مفاتيح في الملفات أو Git. إنشاء سير العمل وحده لا يختبر خدمة خارجية.

الإصدار الحالي:
- يراجع كل سطر مفتاح منفصلًا، ويستخدم معرفًا مثل GEMINI-01 بدل المفتاح.
- يكتشف قوائم Gemini/Groq/Cloudflare ويعرض تصنيفًا مبدئيًا واضح المصدر، لا شهادة قدرة.
- يفحص هوية Hugging Face فقط: قائمة Hub العامة لا تثبت إتاحة الاستدلال المجاني للحساب.
- يطلب قائمة أصوات Inworld؛ لا يولّد صوتًا ولا يعتبر كل معلّق مختبرًا.
- يختبر طلب بحث صور واحدًا لـPexels وUnsplash، وطلب APOD لـNASA. لا يدّعي اختبار الفيديو أو تنزيل المواد أو كل واجهات NASA.
- لا يفترض أن إتاحة الاسم أو نجاح المصادقة يعنيان المجانية أو نجاح التوليد.
- يدعم لاحقًا اختبار نص صغير في Gemini/Groq **فقط بعد اعتماد سياسة مجانية محددة**. ملف السياسة فارغ الآن عمدًا. اختبارات توليد الصور والفيديو والصوت والمؤثرات لم تُنفّذ في هذه الدفعة.
- لا يستورد موديلات إلى التطبيق تلقائيًا. يعرض قائمة مرشحين للمراجعة فقط بعد نجاح اختبار وظيفي وسياسة مجانية مراجعة.

## قبل التشغيل

1. ألغِ المفاتيح التي نُشرت في المحادثة وأصدر بدائل.
2. راجع تغييرات Pull Request، ثم ادمجها لتسجيل سير العمل على الفرع الافتراضي. لا يعمل `workflow_dispatch` لملف جديد غير موجود على الفرع الافتراضي بالطريقة المعتادة.
3. افتح:
   `https://github.com/bitdogemostafa2-sys/youtube-programmer/settings/secrets/actions`
4. اختر **New repository secret** وأضف الأسماء التالية. كل مفتاح في سطر مستقل، حتى20 سطرًا لكل مزوّد. لا تضع علامات اقتباس أو أسماء أو شرحًا بجوار المفتاح.

| المزوّد | اسم Secret | مرجع التقرير |
|---|---|---|
| Gemini | `GEMINI_API_KEYS` | GEMINI-01، GEMINI-02… |
| Groq | `GROQ_API_KEYS` | GROQ-01… |
| Cloudflare | `CLOUDFLARE_ACCOUNTS` | CLOUDFLARE-01… |
| Hugging Face | `HF_API_KEYS` | HUGGINGFACE-01… |
| Pexels | `PEXELS_API_KEYS` | PEXELS-01… |
| Unsplash | `UNSPLASH_API_KEYS` | UNSPLASH-01… |
| Inworld | `INWORLD_API_KEYS` | INWORLD-01… |
| NASA | `NASA_API_KEYS` | NASA-01… |

Cloudflare: كل سطر `ACCOUNT_ID:API_TOKEN` فقط، دون بريد إلكتروني. يجب أن يكون Account ID صالحًا، وأن يملك التوكن صلاحية قراءة كتالوج Workers AI للحساب. لا تفترض أن مفتاح الحساب العام والتوكن المقيد لهما المصادقة نفسها؛ السكربت يستخدم Bearer API Token.

Inworld: قيمة اعتماد API بصيغة Base64 التي تتطلبها Basic authentication، دون إضافة كلمة Basic؛ لا تفكّها أو تنشرها في التقرير.

اتصال Arena أعاد403 عند محاولة قراءة أسماء Secrets. هذا لا يثبت أن القائمة فارغة، ولا يعني فشل مفاتيح المزوّدين. إضافة الأسرار تحتاج صلاحيتك في واجهة GitHub. لا تضعها في Issues أو PR أو Variables أو ملف YAML.

## التشغيل الأول — قوائم فقط

من تبويب **Actions** اختر **Private provider audit** ثم **Run workflow** واختر `inventory`.

- التشغيل يدوي فقط، لا يبدأ مع كل push أو Pull Request.
- استخدم فرعًا موثوقًا ومراجَعًا؛ لا تشغل أسرار المستودع مع كود من طرف غير موثوق.
- لا توجد طلبات توليد في هذا الوضع. طلبات الفحص والبحث قد تستهلك حصة الطلبات المجانية.
- المستودع ظاهر للعامة بحسب فحص إعداداته. راجع صفحة Billing/Actions وسياسة GitHub الحالية بنفسك؛ لم نتحقق من حساب الفوترة أو ضمان تكلفة التشغيل. المستودع العام لا يجعل APIs المزوّدين مجانية.
- زمن أقصى15 دقيقة، دون إعادة تلقائية للطلبات. المهلة أو503 ليست حكمًا بأن المفتاح غير صحيح.

## الملفات الناتجة

حمّل Artifact باسم `provider-audit-report`؛ مدة الاحتفاظ7 أيام:

- `report.md`: جدول لكل معرف مفتاح، الموديلات وتصنيفها والمجانية وحالة الاختبار.
- `report.json`: نفس البيانات المنظمة مع سبب النتيجة ونطاق الاختبار.
- `candidates.json`: العناصر التي اجتازت اختبار النص وسياسة المجانية، لا قائمة مكتشفة غير مختبرة. تبقى فارغة في التشغيل الأول.

التقرير لا يتضمن المفتاح أو Account ID أو البريد أو الرد الخام أو النص المولّد. تغيير ترتيب الأسطر في Secret يغيّر مطابقة الأرقام؛ احتفظ بالترتيب لتفسير التقرير. مخرجات المستودع العام قد تُتاح للآخرين بحسب صلاحيات GitHub؛ لذلك لا تضع بيانات خاصة في أسماء موديلات مخصصة.

إذا لم توجد أسرار أو لم ينجح أي طلب قراءة، يخرج التشغيل برمز فشل مع تقرير يوضح الحالة، وليس علامة نجاح زائفة.

## كيف نعتمد «مجاني ويعمل»؟

بعد قراءة التقرير نراجع توثيق التسعير الرسمي للموديل، والبلد والحصة وصلاحية الحساب. لا نكتفي بقول «المفتاح بلا رصيد»، لأن بعض الحسابات يمكن أن تستخدم فوترة لاحقة.

`tools/provider_audit/free_policy.json` يحتوي قائمة موافقات فارغة. للموديل النصي الذي ثبتت شروطه، نضيف provider/model/task، رابط دليل التسعير، تاريخ المراجعة، وكونه صفر تكلفة بلا رصيد تجريبي ولا تفعيل فوترة. المراجعة تنتهي بعد7 أيام. هذه موافقة بشرية موثقة وليست قدرة للسكريبت على قراءة فاتورة الحساب أو ضمان عدم تغير التسعير.

بعدها فقط يُستخدم `free-tests`، بحد20 طلب توليد في التشغيل كله، ودون retries. لا ينتقل تلقائيًا إلى مزوّد مدفوع. قصر الحد قد يترك موديلات `not_tested_request_limit`؛ لا نسميها فاشلة ولا ندعي اكتمال اختبار جميع الموديلات.

يحتاج استكمال الصور والفيديو والتعليق والمؤثرات إلى موصل اختبار مناسب لكل مهمة وموافقة مجانية مماثلة، ثم التحقق من ملف الناتج. الأصوات تتطلب اختبارًا مستقلًا لكل موديل/صوت؛ اكتشاف قائمة voices لا يساوي نجاح نطق فعلي.
